# Vibe Studio: ТЗ на редизайн интерфейса

Версия 1.0 · 16.10.2026 · Область: `apps/studio/web/src/` (React 19 + Vite, свой CSS)

Цель редизайна: **комфорт и лёгкая управляемость для человека без технического образования**. Пользователь всегда видит: где он находится, что происходит сейчас и какой следующий шаг. Карточки компактнее, обзора больше, технические подробности спрятаны «на второй уровень», но не удалены.

Документ состоит из шести частей:
1. Аудит текущего интерфейса (по экранам, с приоритетами).
2. Концепция оболочки и глобальные удобства.
3. Экраны: раскладка, компоненты, размеры, тексты.
4. Дизайн-система: токены, типографика, иконки, состояния, анимации.
5. Ограничения реализации.
6. Порядок реализации по шагам с критериями приёмки.

Приложение A: скриншоты текущего состояния. Приложение B: словарь интерфейсных текстов.

Приоритеты в аудите:
- **P0** мешает работе или приводит к потере данных; исправить в первую очередь;
- **P1** сильно ухудшает понятность или обзор;
- **P2** полировка, «приятные мелочи».

### 1.8 Что работает хорошо и что сохранить

- Подтверждение удаления агента прямо в карточке («Удалить вместе с задачами (1)? Нет / Удалить») — правильный паттерн без `window.confirm`; его нужно обобщить (см. ConfirmPopover).

- Горизонтальной прокрутки страницы на 390 px нет; `prefers-reduced-motion` учтён; отступы через `env(safe-area-inset-*)`.

## 2. Концепция оболочки

### 2.1 Принципы

1. **Один экран — одно главное действие.** Оно всегда в одном и том же месте: в нижней панели действий, справа.
2. **Где я и что дальше.** Степпер проекта показывает 4 шага и их состояние. Под шагом всегда видна фраза-подсказка.
3. **Обзор важнее подробностей.** Карточки в 1–2 строки, подробности в боковой панели (drawer) по клику.
4. **Технику — на второй уровень.** id, папки, ветки, команды проверки, модель и движок не удаляются, а прячутся в «Для опытных», «Подробности» и «Настройки запуска».
5. **Ничего не теряется.** Черновики ТЗ и плана переживают переключение шагов. Опасные действия подтверждаются прямо в интерфейсе.
6. **Без перегруза.** Каждая фишка ниже решает конкретную проблему из аудита. Всё, что не решает, отвергнуто (см. 2.9).

### 2.2 Раскладка оболочки (десктоп ≥ 1024 px)

```
┌───────────────┬──────────────────────────────────────────────────────────────────────────┐
│ [V] Vibe Studio│  coffee-shop  ~/VibeProjects/…  │ (1)ТЗ ✓ ─ (2)Команда ✓ ─ (3)Запуск ● ─ (4)Результат │ [⌕ Ctrl K] │
│ [+ Новый проект]├──────────────────────────────────────────────────────────────────────────┤
│               │                                                                          │
│ ПРОЕКТЫ        │                         КОНТЕНТ ШАГА                                    │
│ ● coffee-shop  │                (своя прокрутка, max-width по экрану)                    │
│ ◌ my-school    │                                                                          │
│ ○ landing      │                                                                          │
│               │                                                                          │
│               │                                                                          │
│ ───────────── ├──────────────────────────────────────────────────────────────────────────┤
│ ● Демо-агенты ⌄│ Подсказка: «6 агентов · 6 задач · 4 этапа»     [Сохранить] [▶ Запустить агентов] │
│ ☾ Тема  ⇆ Плотн.│                                                       (панель действий, 56 px) │
└───────────────┴──────────────────────────────────────────────────────────────────────────┘
  сайдбар 232 px              шапка проекта 52 px; панель действий 56 px
```

Сетка: `display:grid; grid-template-columns: var(--sidebar-w) minmax(0,1fr); height:100dvh`. Правая часть — колонка из трёх строк: `auto` (шапка проекта), `minmax(0,1fr)` (контент, `overflow:auto`), `auto` (панель действий). Страница целиком не прокручивается, прокручивается только контент. Поэтому шапка и панель действий не перекрывают контент: проблема L1 исчезает конструктивно.

**Демо-режим.** Вместо баннера в шапке проекта и вверху сайдбара — чип `Демо` (иконка `Info`). По клику открывается поповер с текстом баннера. При первом открытии демо-сборки поповер открыт сам и закрывается кнопкой «Понятно». Факт закрытия запоминается в `localStorage` (`vibe.demoNoticeSeen`, в try/catch).

### 2.3 Сайдбар (232 px, сворачивается до 56 px)

Состав сверху вниз:

| Блок | Содержимое | Размеры |

| Логотип | знак `V` 24 px + «Vibe Studio» (600, 15 px). Клик ведёт на главную «Проекты» | высота 52 px, совпадает с шапкой проекта |

### 2.4 Шапка проекта и степпер

Шапка проекта высотой 52 px, нижняя граница `--border`:
- слева название проекта (`plan.project.name` или `details.name`, 15 px/600, ellipsis, max 280 px). Под ним путь папки `~/VibeProjects/…` (12 px, `--text-3`, mono), если позволяет ширина ≥ 1280. Клик по пути копирует его и показывает тост «Путь к папке скопирован»;
- по центру или слева после названия — **степпер**;
- справа кнопка-поле `⌕ Поиск и команды  Ctrl K` (180 px; на < 1280 только иконка `Search` с тултипом).

**Степпер: 4 шага.** Внутренние id маршрутов сохраняются (`spec`, `plan`, `run`, `files`), чтобы не ломать hash-ссылки.

| Шаг | Подпись | Иконка | Состояния |
|---|---|---|---|
| 1 | ТЗ | `FileText` | `current` / `done` (есть `details.plan`) |
| 2 | Команда и план | `Users` | `locked` без плана (тултип «Сначала опишите задачу на шаге ТЗ») / `done`, если есть `snapshot` / счётчик «6 агентов» в тултипе |
| 3 | Запуск | `Rocket` | `locked` без плана / `live`, когда `running` (пульсирующая точка + «3/6» рядом с подписью) / `done` при `snapshot.status==='done'` / `error` при `failed` (красная точка) / `stopped` (жёлтая точка) |

### 2.6 Настройки: тема, плотность, движок

- **Тема.** Три значения: «Как в системе» (по умолчанию), «Тёмная», «Светлая». Хранится в `localStorage['vibe.theme']`. «Тёмная/Светлая» ставят `document.documentElement.dataset.theme`, «Как в системе» удаляет атрибут. Чтобы не было вспышки, тема применяется синхронно до `createRoot` в `main.tsx`. Иконка в сайдбаре показывает текущее значение, клик открывает меню из трёх пунктов.
- **Плотность.** «Обычная» (по умолчанию) и «Плотная». Атрибут `data-density="compact"` на `<html>` переопределяет токены отступов и высот (4.5). `localStorage['vibe.density']`. Даже «Обычная» плотность заметно компактнее текущего интерфейса.
- **Движок и модель.** Поповер из низа сайдбара (ширина 320 px):
  - «Кто выполняет работу»: радио-список движков из `/api/engines`. Недоступные заблокированы, под ними `hint` (12 px, `--text-2`);
  - «Модель» (только для `claude-code`): сегментированный список из `MODELS` с пояснениями «баланс / максимум качества / быстро и дёшево»;
  - сноска: «Этот выбор используется и для составления плана, и для работы агентов».
  Хранение прежнее: `localStorage['vibe.engine']`.

### 2.8 Состояние и маршрутизация

- Тип `Tab` и hash-маршрутизация не меняются: `#coffee-shop/run`. В демо (`HASH_ROUTING=false`) — состояние в памяти, `location.hash` не трогать.
- **Сброс прокрутки (S1).** При смене шага или проекта у контейнера контента вызывается `scrollTo({top:0})`.
- **Черновик плана (S2)** поднимается из `PlanTab` на уровень `ProjectView` в новый хук `usePlanDraft(project)`: `{ draft, dirty, update, save, reset }`. Его используют шаг 2, панель действий и диалог ухода. `useProject` не меняется.
- **Черновик ТЗ (T1).** Текст ТЗ при каждом изменении сохраняется с задержкой 500 мс в `localStorage['vibe.spec.' + name]` (в try/catch). При открытии шага 1: если `details.spec` пустой и черновик есть, подставить черновик и показать тост «Восстановлен черновик ТЗ». Если оба есть и различаются, приоритет у черновика, рядом с полем ссылка «Вернуть сохранённую версию». После успешного `/plan` черновик удаляется.
- **Умное открытие проекта (P4).** Из списка проект открывается на нужном шаге: `running` → `run`; `lastRun` → `run`, если `failed`/`stopped`, и `files`, если `done`; `hasPlan` → `plan`; иначе `spec`.
- Настройки запуска (параллельность, попытки, полный доступ) хранятся в `localStorage['vibe.runSettings']`. Их же передаёт «Запустить заново» (исправление R5, только клиент).

### 2.9 Что сознательно не делаем

| Идея | Решение | Почему |
|---|---|---|
| Перетаскивание задач между этапами (drag-and-drop) | Отвергнуто | Этап вычисляется из зависимостей. Перетаскивание создаёт неочевидные связи и сложно в реализации без библиотек. Вместо него «+ задача в этап» и выбор «После каких задач» в панели |
| Графы зависимостей со стрелками | Отвергнуто | Перегружает экран; подсветка связей при наведении даёт тот же смысл |
| Подсветка синтаксиса кода | Отложено (P2+) | Пользователь не должен читать код. Номера строк и перенос дают достаточно, лишняя зависимость не нужна |
| Системные уведомления браузера (Notification API) | Отвергнуто | Запрос разрешения пугает. Хватает заголовка вкладки и тоста |
| Онбординг-тур поверх интерфейса | Отвергнуто | Хватает степпера, подсказок в панели действий и пустых состояний |
| Удаление и переименование проекта | Не входит | Нет серверного API, а менять его нельзя |
| Три и более режимов плотности, кастомизация цветов | Отвергнуто | Перегруз; двух режимов достаточно |

- Секции выводятся, только если есть данные. Порядок зависит от статуса:
  - `pending` и `blocked`: «Что нужно сделать», «Как понять, что готово», «Начнётся после» (список задач-предшественников со статусами). Для `blocked` сверху плашка `--warn-soft`: «Не запускалась: не получилась задача «…», от которой она зависит»;
  - `running`, `checking`, `merging`: сверху «Сейчас: {lastAction}» с `LoaderCircle`, затем «Что делал агент» (раскрыто, последние 20 событий), затем описание;
  - `failed`: сверху плашка `--bad-soft` «Не получилось за {attempts} {попытку/попытки/попыток}» и `error` (обычный шрифт; длинное — свернуть после 6 строк, «Показать полностью»), затем подсказка «Что можно сделать: уточнить описание задачи в плане и запустить заново» + кнопка «Открыть в плане» (шаг 2 с открытым Drawer этой задачи);
  - `done`: «Отчёт агента», «Изменённые файлы», затем описание и критерии.
- Описание и критерии берутся из `details.plan.tasks.find(t => t.id === task.id)`. Если задачи в плане уже нет (план поменяли после запуска), секции не показываются.
- Значки файлов: `+` `--ok` (added), `~` `--warn` (modified/renamed), `−` `--bad` (deleted); путь mono 12.5 px; клик → шаг 4 с этим файлом (`FilesTab` получает новый проп `initialPath`).
- «Подробности» (свёрнуто): «Ветка», «Попыток», «Время» (начало–конец, длительность), «Стоимость» (если > 0), «Внутреннее имя» (`id`). Подписи 12 px `--text-3`, значения mono 12.5 px.
- Клавиши: Esc закрывает; J/↓ — следующая, K/↑ — предыдущая задача (порядок как на доске слева направо, сверху вниз). Кнопки `ChevronLeft/ChevronRight` 28 px.
- Фокус: при открытии — на заголовок панели (`tabIndex=-1`); при закрытии — обратно на карточку. На < 1280 (с затемнением) фокус заперт внутри панели, `role="dialog" aria-modal="true"`; на ≥ 1280 — `role="complementary"` с `aria-label="Задача: …"`.

Все токены — CSS-переменные на `:root`. Новая структура стилей (Vite склеит всё в один `app.css`, демо-сборка не меняется):

### 4.5 Типографика

### 4.6 Иконки — lucide-react вместо эмодзи

Принято. Все эмодзи из интерфейса удаляются (критерий: `grep -P "[\x{1F300}-\x{1FAFF}\x{2600}-\x{27BF}\x{23E9}-\x{23FA}\x{25A0}-\x{25FF}]" web/src` ничего не находит, кроме строк-данных демо-бэкенда, если там есть).

Правила: иконки 16 px (по умолчанию), 14 px в плотных строках, 20 px в итогах и пустых состояниях (32 px), `strokeWidth={1.75}`, цвет `currentColor`. Декоративные иконки — `aria-hidden`. У кнопок-иконок обязательны `aria-label` и тултип. Импорт поимённо (`import { Play } from 'lucide-react'`), тогда tree-shaking оставит только используемые.

| Было | Стало |

### 4.9 Анимации

| Токен | Значение | Где |
|---|---|---|
| `--dur-fast` | 120 ms | hover, цвет, нажатие |
| `--dur-base` | 180 ms | поповеры, тосты, раскрывашки |
| `--dur-slow` | 240 ms | Drawer, шторки |
| `--ease-out` | `cubic-bezier(.2,.8,.2,1)` | появление |
| `--ease-in` | `cubic-bezier(.4,0,1,1)` | исчезновение (длительность ×0,75) |

Анимируются только `opacity` и `transform`. Ширина прогресс-бара — `transition: width 400ms var(--ease-out)`. Постоянные анимации — только у работающего: вращение `LoaderCircle` (1 с), пульсация точки «идёт работа» (1,6 с, opacity .4↔1), штриховка сегмента прогресса. При `prefers-reduced-motion: reduce`: Drawer и поповеры — без сдвига, только opacity за 120 мс; пульсация и штриховка отключены; спиннер не вращается, вместо него статичная иконка `LoaderCircle` + текст статуса. Существующее глобальное правило в конце `styles.css` перенести в `base.css`, исключив `opacity`-переходы (они остаются ≤ 120 мс).

## 5. Ограничения реализации

1. **Не менять** `web/src/api.ts`, `web/src/useProject.ts`, сервер (`apps/studio/server/*`), пакет `@vibe/core` и формат данных (`Plan`, `RunSnapshot`, `FeedItem`, `ProjectSummary`, `ProjectDetails`). Всё новое — на клиенте: новые хуки (`usePlanDraft`, `useActionBar`, `useCommands`, `useToast`, `useHotkeys`, `useLocalSetting`) и компоненты.
2. **Не использовать** `window.confirm`, `window.alert`, `window.prompt`: все подтверждения — `ConfirmPopover` или `Dialog` (2.7).
3. **Обе темы.** Каждый экран и состояние проверяется в `colorScheme: 'dark'` и `'light'`, а также при `data-theme="dark|light"` поверх противоположной системной темы. Цвета задаются только токенами; захардкоженные `#hex` в компонентах запрещены (кроме `tokens.css`). Сейчас `.avatar` использует `color:#10121a` — убрать.
4. **Телефон 390 px:** нет горизонтальной прокрутки страницы (`document.documentElement.scrollWidth <= innerWidth`). Внутренняя горизонтальная прокрутка допустима только у явно обозначенных лент (чипсы шаблонов, полоса агентов, чипсы стека) с затуханием края. Боковой отступ ≥ 16 px с учётом `safe-area`.
5. **Демо-сборка** `node scripts/build-demo.mjs <путь>` работает и даёт один HTML-файл (CSS и JS встроены, шрифты — base64 внутри CSS). Нельзя подключать ресурсы из сети (Google Fonts CDN и т. п.), нельзя динамически импортировать чанки (`codeSplitting: false`) и полагаться на `location.hash`. Размер ≤ 700 КБ.
6. **Навигация в демо** — без `location.hash` (`HASH_ROUTING = !__VIBE_DEMO__`); все новые переходы (шаги, Drawer задачи, экран файла на телефоне, палитра) идут через состояние React. В обычном режиме hash-маршруты `#<проект>/<spec|plan|run|files>` продолжают работать, включая кнопки «назад/вперёд» браузера. Drawer задачи в hash не пишется.
7. **`localStorage`** — только для удобств одного пользователя (тема, плотность, сайдбар, лента, настройки запуска, черновик ТЗ, «демо-уведомление видели»). Каждое чтение и запись в `try/catch`; без хранилища интерфейс работает с умолчаниями. Ключи с префиксом `vibe.`.
8. **Зависимости:** добавить только `lucide-react`, `@fontsource/onest`, `@fontsource/jetbrains-mono` (точные версии из 4.5). Никаких UI-китов, CSS-фреймворков, библиотек позиционирования и markdown.
9. **Доступность:** все интерактивные элементы — `<button>`/`<a>`/поля (не `div onClick`); видимый фокус; Esc закрывает верхний слой; у иконок-кнопок `aria-label`; живые области: тосты `aria-live="polite"`, фраза статуса запуска `aria-live="polite"` с ограничением частоты (обновлять озвучивание не чаще раза в 10 с), лента — без `aria-live`.
10. **Типы:** `pnpm typecheck` и `pnpm test` проходят. Текущие `aria-label` полей «Название проекта» и «Техническое задание» сохранить, на них опираются сценарии проверки.
11. **Производительность:** лента до 500 событий (`FEED_LIMIT`) рендерится без подтормаживаний. При необходимости — отрисовка только последних 200 + кнопка «Показать раньше». Тикер `useNow` (1 с) — только пока идёт работа.
12. **Тексты** — только по-русски, на «вы», без жаргона в основном слое (слова «ветка», «merge», «scope», «id», «main» допустимы только в «Подробностях» и «Для опытных»). Словарь — Приложение B.

## Отклонения при реализации

1. **Шрифты.** Подключены собственным `styles/fonts.css`, а не CSS-файлами `@fontsource/*`: те ссылаются и на woff2, и на woff, и в демо-сборке встроились бы оба формата (вдвое больше). Оставлен только woff2 с `unicode-range` (cyrillic + latin). Начертание Onest 700 не подключено: по 4.5 оно нужно только логотипу, а без него демо укладывается в бюджет (657 КБ при лимите 700 КБ); логотип и жирный текст набраны 600.
2. **Демо-сборка.** В `scripts/build-demo.mjs` добавлен `<meta charset="utf-8">`: после встраивания шрифтов кириллица оказывалась дальше окна автоопределения кодировки, и при открытии через `file://` текст превращался в «кракозябры».
3. **`useActionBar` → компонент `<ActionBar …/>`.** Экран рендерит панель там, где ему удобно, а содержимое уходит порталом в слот оболочки. Контракт тот же (`hint`, `secondary`, `primary`, `Action` с `confirm`), но обработчики всегда актуальные и не нужна синхронизация состояния через контекст. Действия панели автоматически попадают в палитру команд и нажимаются через ту же кнопку (с подтверждением, если оно есть).
4. **Состояние шага «ТЗ»** (текст, вопросы, ответы, работа планировщика) поднято на уровень проекта (`useSpecFlow`), как и черновик плана: можно уйти со страницы во время составления плана, вернуться и увидеть прогресс; по готовности приходит тост «План готов».
5. **Новый агент / новая задача** добавляются в план только по «Готово» в шторке; «Отмена» ничего не оставляет (в исходном интерфейсе пустой агент оставался в плане).
6. **Тексты оркестратора** в ленте («…и влито в main») показываются как «…и сохранено в проекте» — простая замена на клиенте, ядро не менялось.
7. **Степпер на ширине < 1280** использует короткие подписи («ТЗ / Команда / Запуск / Итог»), иначе вместе с сайдбаром шаги на 1024 px наезжали друг на друга. Чип «Демо» на десктопе с раскрытым сайдбаром показывается только в сайдбаре (в шапке — когда сайдбар свёрнут или скрыт), чтобы не было двух одинаковых чипов рядом.
8. **Лента событий на 768–1279** открывается шторкой справа без затемнения (на телефоне — нижней шторкой с затемнением), вместо отдельной нижней шторки на планшете.
9. **Кнопка в итоге запуска** называется «Что сделала каждая задача» (вместо «Посмотреть файлы задач»): она раскрывает список задач с первой строкой отчёта, а файлы открываются на шаге «Результат».
10. **Заголовок вкладки браузера** с «▶ 3/6» и «✓»: символы записаны в коде escape-последовательностями, чтобы проверка «нет эмодзи в интерфейсе» (4.6) оставалась строгой; в самих экранах эмодзи нет.
11. **Отложено (P2):** вид «Этапы» на дашборде; возврат к дереву файлов системным жестом «назад» на телефоне (в демо нельзя трогать историю/адрес — работает кнопка «Назад к файлам»); «ещё N» с поповером для очень длинной полосы агентов (полоса переносится максимум на две строки, на телефоне прокручивается); группировка ленты подряд идущих событий сделана только по аватару и имени, без схлопывания строк.
